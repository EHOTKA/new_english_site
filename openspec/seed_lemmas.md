# OpenSpec: Инициализация и наполнение словаря лемм (`global_lemmas`)
Версия: 1.0.0  
Дата выполнения: 16 сентября 2026 г.  
Статус: Завершено

---

## 1. Контекст и цели задачи

Таблица `global_lemmas` в реляционной схеме базы данных (`openspec/bd.md`) является фундаментом для сопоставления слов из субтитров и определения сложности лексики.

**Требования к задаче:**
1. Получить открытые данные по частотности и частям речи (POS) для английского языка.
2. Подготовить и очистить список из **10 000** наиболее частотных разговорных английских лемм.
3. Обогатить каждую лемму корректной частью речи (`part_of_speech`), рангом популярности (`frequency_rank`) и уровнем CEFR (`cefr_level`: `A1`–`C2`).
4. Реализовать сидирование через формирование SQL-скрипта (`seed_global_lemmas.sql`) и прямой запуск через Python/`psycopg2`.
5. Применить сиды к базе данных в Docker-контейнере (`postgres_container_eng`) и верифицировать результат.

## 2. Проблемы исходного решения и их устранение

| Проблема | Причина | Решение |
|---|---|---|
| **HTTP 404 при скачивании NGSL 1.3** | Устаревший URL к CSV-файлу на внешнем сайте. | Переход на локально доступный и верифицированный корпус CEFR и OpenSubtitles. |
| **Вырождение POS в `'other'` (100%)** | Из-за 404 срабатывал аварийный fallback по неразмеченному списку слов, где POS по умолчанию был `'other'`. | Парсинг и маппинг тегов Penn Treebank из специализированного корпуса в человекочитаемые части речи. |
| **Словоформы и сокращения вместо лемм** | В сыром списке частот присутствовали формы `'s`, `'t`, `relying`, `differed`, `children`. | Каноническая лемматизация форм через связку `lemma_word_id`, суммирование частотности форм к лемме (например, `be` объединяет частоты `am`, `is`, `are`, `was`, `were`, `been`). |
| **Шум и имена собственные (NNP/NNPS)** | Частотный список субтитров насыщен именами актеров, персонажей и топонимами. | Фильтрация по доле использования слова как имени собственного: слова с доминирующим NNP отсекаются. |

## 3. Источники данных

Все исходные данные сохранены в директории `docker/data/`:
1. **`docker/data/en_50k.txt`** (OpenSubtitles unigram frequency list, 50 000 записей):
   - Отражает реальную частоту употребления слов в кинематографе и разговорной речи.
2. **`docker/data/word_cefr_minified.db`** (SQLite датасет, ~20 МБ):
   - Содержит таблицы: `words`, `pos_tags`, `word_pos`.
   - Хранит нормализованные связи словоформ с леммами, частоты в корпусах, теги частей речи (Penn Treebank) и непрерывные уровни CEFR.

## 4. Архитектура скриптов и алгоритм обработки

### 4.1. Маппинг частей речи (Penn Treebank -> POS)
Теги частей речи нормализованы в категории:
- `NN`, `NNS` $\rightarrow$ `noun`
- `VB`, `VBD`, `VBG`, `VBN`, `VBP`, `VBZ`, `MD` $\rightarrow$ `verb`
- `JJ`, `JJR`, `JJS` $\rightarrow$ `adjective`
- `RB`, `RBR`, `RBS`, `WRB` $\rightarrow$ `adverb`
- `PRP`, `PRP$`, `WP`, `WP$` $\rightarrow$ `pronoun`
- `IN`, `TO` $\rightarrow$ `preposition`
- `DT`, `WDT`, `PDT` $\rightarrow$ `determiner`
- `CC` $\rightarrow$ `conjunction`
- `CD` $\rightarrow$ `numeral`
- `UH` $\rightarrow$ `interjection`
- `RP` $\rightarrow$ `particle`

### 4.2. Маппинг CEFR
Непрерывный уровень сложности переводится в ENUM `cefr_level_enum`:
- $< 1.5 \rightarrow$ `A1`
- $1.5 .. 2.49 \rightarrow$ `A2`
- $2.5 .. 3.49 \rightarrow$ `B1`
- $3.5 .. 4.49 \rightarrow$ `B2`
- $4.5 .. 5.49 \rightarrow$ `C1`
- $\ge 5.5 \rightarrow$ `C2`

### 4.3. Реализованные файлы в `docker/`:
- **`docker/generate_seed_sql.py`**:
  - Загружает SQLite-базу и частотный словарь субтитров.
  - Агрегирует инфлексии в базовые леммы.
  - Отсеивает стоп-шумы, фрагменты и имена собственные.
  - Определяет доминирующую часть речи и средневзвешенный CEFR.
  - Формирует `seed_global_lemmas.sql` порциями по 500 записей внутри единой транзакции (`BEGIN ... COMMIT`).
- **`docker/seed_global_lemmas.py`**:
  - Python-утилита для прямой вставки через `psycopg2` (`execute_values`).
  - Поддерживает флаги `--limit` и `--dry-run` для предпросмотра без изменения БД.
- **`docker/seed_global_lemmas.sql`**:
  - Готовый файл сидирования на 10 000 строк.

## 5. Выполненные шаги по сидированию

1. **Генерация SQL-сидов:**
   ```bash
   python3 docker/generate_seed_sql.py --limit 10000
   ```
   Сформирован файл `docker/seed_global_lemmas.sql`.

2. **Применение сидов в PostgreSQL (Docker):**
   ```bash
   docker exec -i postgres_container_eng psql -U postgres_user -d postgres_db < docker/seed_global_lemmas.sql
   ```

3. **Верификация результата в базе данных:**
   - Общее количество записей: **10 000**.
   - Наличие первичных ключей (`UUID`), уникальность лемм соблюдена.
